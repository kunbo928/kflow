# k-architecture

先读项目地图。需要持久化审计或设计时，通过 `kflow work` 创建或恢复 `works/architecture-{slug}/`；稳定结论写入 `spec.md`，活动状态写入 `work.md`。

先限定系统或模块边界，再检查真实归属、依赖、调用方负担、内聚、信息隐藏、测试接缝、近期变更热点和现有项目地图/正式文档。代码与可执行契约是证据，不能只根据图判断健康度。

报告现状、具体摩擦、候选接缝、方案与取舍、受影响消费者、迁移约束，并把置信度标为“明确建议”“值得探索”或“推测”。只有当前证据无法回答真实决策时才使用调研或原型。架构结论不授权代码改动。

已批准的局部行为等价改进转 `k-refactor`；多个依赖交付项或迁移阶段转 `k-roadmap`；发现缺陷转 `k-issue`。接受的架构决定同步到正式归宿和项目地图指针，并报告 `work.md` 是否具备删除条件，由用户决定。
