# 写给 Agent 的文档

同一套杠杆适用于 `AGENTS.md`、project-map、`SKILL.md` 和 reference：让 Agent 每次走同一过程，而不是每次产出同一段文字。

## 指针

指针点名上下文外的材料，并写清何时去读。措辞决定会不会被够到。弱指针后面放必须读的材料，是方差缺陷：先改措辞，改不动再内联。

- 触发词放句首。
- 每个真正不同的分支一个触发；同义词不是新分支。
- 正文已经自报身份的，指针里不要再写一遍。
- 始终加载的指针（skill `description`、`AGENTS.md` 的一行）每个词都要挣到位置。

## 信息层级

内容只有两类：步骤（按序做）和参考（按需查）。

1. 文内步骤 — 立刻要做的。
2. 文内参考 — 同文查阅。
3. 披露参考 — 另文件，指针命中才读。

每个分支都需要的留在文内；只有部分分支才读的推到 reference。概念的定义、规则、例外放在同一标题下。单文件超过 300 行先拆，不靠堆句子。

## 完成条件

每一步写清怎样算做完：能区分做完和没做完，并且要求足够具体（「每个改动的模块都交代了」优于「列一份变更」）。模糊界限先改句子；改不清再把后续步骤拆到另一次加载。

## 先导词

用模型已经认识的短词锚定行为（`red`、`接缝`、`frontier`），重复的是词，不是整段定义。先找现成词，再自造。

用肯定句写目标行为。禁令只有在无法正向表达的硬护栏才写，并紧跟要做什么。

## 修剪

- 每个意思一个真源。重复同一意思会抬高它在层级上的权重。
- 环境也是真源：`package.json` scripts、目录、`--help`。文档只缓存查找昂贵或环境不会说的约定、理由、坑。
- 逐句问：这句话是否还改变行为？不改就整句删。默认服从的指令是空操作。
