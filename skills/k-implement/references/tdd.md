# TDD

对着已确认接缝做 red → green。每一轮开始前先读本节，不要写完再对照。

## 好测试

测试穿过调用方可见的公共接口，验证行为，不锁实现。改内部结构时测试应仍成立。测试名读起来像规格：「用户可以用有效购物车结账」。

## 接缝

接缝是观察行为而不伸进内部的公共边界。测试只打在契约已写下的接缝上；未确认的接缝不写测试。接口形状本身还在争时，先退回主人拷问，不在实现里发明接缝。

## 反模式

- **绑实现**：mock 内部协作者、测私有方法、绕过接口查库。重构即红、行为未变，就是它。
- **同义反复**：期望值用代码同一套算法现算（`expect(add(a,b)).toBe(a+b)`）。期望必须来自独立真相：字面量、手算例子、spec。
- **横切**：先写完全部测试再实现。批量测试验证的是想象中的形状。改成纵向切片：一个测试 → 一次最小实现 → 再下一发 tracer bullet。

## 循环规则

- **先 red 再 green。** 先看失败，只写让它通过的最小代码。不为后面的测试预留功能。
- **一次一片。** 一轮一个接缝、一个测试、一份最小实现。
- **重构不是这一环。** 结构改动走已批准的 refactor 与审查，不塞进 red → green。
