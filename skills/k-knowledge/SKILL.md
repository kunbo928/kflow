# k-knowledge

把下次还要用的项目事实写回已有入口。写法点名 `k-author`。验收场景、本次方案和任务进度只留在 Work spec，不进地图。

## 授权

用户说「记住 / 更新 / 退役」、接受 owning task 给出的晶化候选，或 Work 收尾扫描，就是本次精确内容的写入授权。新建协作规则、改项目边界、删除既有入口仍需用户显式授权。没有可追溯证据不写；不编造。

## 落点

按单一 owner：

1. **机械 guard 优先**：能由测试、checker、lint、类型或 CLI 阻止的重复错误，在已有实现授权且不扩大 scope 时直接机械化；否则只建议进入对应 owning task。
2. **怎么干活**（验证命令、协作规则、何时读地图）写入根 `AGENTS.md`。文件已存在时只补有边界的区块；冲突交 owner。
3. **项目是什么**（边界、区域、指针、校验方式、区域短介绍）写入 `.kflow/project-map/`。能从代码、测试、`package.json` 查到的不抄。
4. **结构性决定**进入项目既有 ADR 惯例，且须同时满足难回退、缺少上下文会意外、源于真实取舍。
5. 目标不存在时请 owner 选择，不发明目录。

校准：代码或命令已经变了，以代码为准修指针，不写新介绍。同一句打架，校准赢。一次只写用户拍板过的内容。

## 完成

报告写入或更新的路径与一句话摘要。收尾必扫；用户可随时「记住」。
