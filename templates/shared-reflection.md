# 写代码时的反射检查

`k-feat-impl` 和 `k-issue-fix` 共用。它不是格式规则，而是在 AI 开始漂移时叫停。

## 触发器

| 触发场景 | 停下来问自己 |
|---|---|
| 往长文件追加代码 | 新增的是已有职责延伸，还是第 N+1 件事？ |
| 往多方法类加方法 | 是核心职责自然扩展，还是 god class 信号？ |
| 函数超过一屏 | 这个函数在做几件事？ |
| 加 `if (特殊情况)` 分支 | 抽象维度是否选错？ |
| copy-paste | 能抽共用，还是只是字面相似？ |
| 函数加第 4+ 个参数 | 函数是否做太多？ |
| 新写万能 helper / util | 真没归属，还是懒得找归属？ |

## 处理

触发后先停下来说明信号。拆 / 新建 / 重命名 / 抽共用会让改动超出现有 steps 范围，必须和用户对齐后再决定：

- 纳入当前推进
- 记为顺手发现留后续
- 回到 design / analysis 更新方案

不许偷偷拆完继续写，也不许忽略信号硬冲。
